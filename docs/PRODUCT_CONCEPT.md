## 0. Коротко

1. **Сила Veles в замкнутой петле, а не в отдельных функциях.** Петля такая: витрина готовых ботов → личная копия настроек → обязательный бэктест → запуск на своей бирже через API-ключ без права вывода → статистика и уведомления в Telegram → ссылка-шеринг → оплата только с прибыли.
2. **Больше всего пользователи Veles жалуются на потери и ликвидации при усреднении (DCA и мартингейл).** Особенно тяжело, когда на одном счёте работают несколько ботов. Следом идут сбои исполнения, модель оплаты (процент с валовой прибыли, предоплаченный баланс) и бэктест, который «врёт».
3. **Наши преимущества уже есть в коде.**
   - В каждой сделке стоит стоп.
   - Размер позиции считается от риска в процентах депозита.
   - Бэктестер Genome проверяет результат вне выборки (out-of-sample), методом Монте-Карло и walk-forward.
   - Трекер считает исход каждого сигнала.
   - Счёт защищён: пауза после серии стопов, дневной лимит убытка в R, корреляционный лимит.
   - Челлендж держит дневную дисциплину.
4. **Рекомендация: вариант C.** Сначала механика Veles поверх наших трёх стратегий (вариант A). Ядро займёт 9–10 недель после переноса. Потом конструктор по этапам: свои фильтры → свой вход со стопом → сетка или DCA с жёсткими ограничителями. Это совпадает с решением D13.
5. **Сайт.** Оставляем красный Liquid Glass из Mini App и переводим на него лендинг: сейчас лендинг на оранжевой теме `aura-theme.css`. Первый экран станет «песочницей бота»: посетитель выбирает стратегию и монету, сразу видит кривую бэктеста и кнопку «Запустить такого бота».

**Ограничения исследования.** Все факты о Veles собраны из нескольких источников: поисковые сниппеты, справка help.veles.finance, сторонний открытый код поверх API Veles (veles-tools, veles-bt) и скриншоты кабинета за февраль–март 2026 из стороннего блога. Живой лендинг Veles и его анимации не наблюдались [SP §0, §10; VD §4]. Поэтому интерактив лендинга мы не копируем, а проектируем свой.

### 2.3 Вывод

Ядро механики Veles берём целиком: витрина → копия → бэктест → запуск → статистика → шеринг → оплата по результату. При этом закрываем четыре главные боли:

- усреднение → стоп и риск-бюджет счёта;
- непрозрачная витрина → три раздельных источника цифр;
- оплата с валовой прибыли из предоплаты → чистая прибыль, постоплата;
- бэктест без проверки вне выборки → наш бэктестер с OOS, Монте-Карло и walk-forward.

### 3.2 Что у нас называется «ботом»

**Бот CHM** — это набор из следующих полей:
- стратегия: Уровни (LEVELS), SMC или Объём + MA (VOLUME);
- направления;
- таймфрейм;
- набор параметров (гены: у LEVELS 17, у SMC 12, у VOLUME 22 [GEN §1.2], плюс пользовательские `setup_*` у VOLUME);
- фильтры входа: мин. качество, только по тренду, контртренд, BTC-корреляция и т. д.;
- режим: только сигналы, автотрейд с подтверждением или автотрейд «авто»;
- биржа, риск на сделку, плечо, макс. число сделок.

Сейчас всё это хранится по пользователю:
- `trader_settings`: LEVELS shared/long/short, автотрейд, риск;
- `smc_cfg` (JSON);
- kv `volume_cfg_<uid>`;
- `optimizer_params`.

Источник: [PLAN §1.2, §2.1; GEN §1.12–1.14].

Возможны две реализации:

| | Слоты (для A) | N ботов (для B, возможно A+) |
|---|---|---|
| Суть | До 3 ботов у пользователя, по одному на стратегию. Бот = текущая конфигурация стратегии плюс метаданные: имя, `origin_id` витрины, снимок «до копирования» | Несколько экземпляров одной стратегии с разными параметрами |
| Движок | Не меняется: сканеры уже работают по стратегиям пользователя, мемоизация по ключу конфигурации сохраняется [PLAN §2.2 п.2]. Golden-тесты не затрагиваются | Ключ бота нужен во всех сканерах, в реестре дедупликации, в лимитах автотрейда и в статистике. Это ломает принцип 1:1 из [PLAN §0 п.2] |
| Ограничение | Два LEVELS-бота с разными параметрами одновременно запустить нельзя | Больше CPU на одном ядре: каждый бот добавляет свой ключ конфигурации |
| Особенность | У LEVELS раздельные long/short-конфиги (sparse merge) [PLAN §1.2]. Бот «Уровни» может торговать LONG на 1H и SHORT на 4H, в UI это один бот с двумя «ногами» | — |

**Рекомендация: в A делаем слоты.** N ботов переносим на этап B.

Шкала риска (предложение, считается по данным бэктеста и live):

| Уровень | Правило |
|---|---|
| 1 | p95 просадки по Монте-Карло ≤ 5R, плечо ≤ 3× |
| 2 | p95 ≤ 8R |
| 3 | p95 ≤ 12R |
| 4 | p95 ≤ 18R |
| 5 | p95 > 18R или плечо ≥ 10× |

Подпись всегда даётся словами, например «при риске 1% худшая серия ≈ −8% депозита».

**Карточка бота, полный экран:**
1. Шапка: имя, стратегия, ТФ, монеты, бейдж источника, дата публикации, «обновлено N мин назад».
2. Вкладки **Live / Бэктест / Копии** с одинаковым набором метрик. Источники не смешиваются.
3. Кривая equity в R с осями и периодом. Под ней «подводная» кривая просадки. Переключатель «R / % при риске N%».
4. Метрики: сигналов, закрыто, WR (Wilson), ΣR, PF, EV, макс. просадка, среднее время в сделке, лучшая и худшая монета, результат по сессиям и по контексту тренда.
5. Последние 20 сигналов из трекера: статус-чипы (TP1, БУ, SL, EXPIRED); тап открывает существующую карточку сигнала с графиком и лестницей R [UI §4.3].
6. «Как он торгует»: текст из параметров. Пример для Уровней: «ищет отбой и пробой уровней на 1H, входит при качестве от 5/10, цель не меньше 2R, стоп за зоной».
7. «Что видит сейчас» (M12) и «Где не работает» (by_context, сессии).
8. Параметры (раскрываются, значения генов).
9. Кнопки: «Копировать», «Тест на моих монетах», «Подобрать», «Поделиться».

**Шторка «Копировать»:**
1. **Режим:** Демо / Сигналы / Автотрейд с подтверждением / Автотрейд авто. По умолчанию Демо.
2. **Биржа:** только для автотрейда. Если ключей нет, предлагаются «Подключить» и «Bybit Demo».
3. **Риск на сделку** (0,25–3%) и **плечо**. Рядом живая строка риск-панели: «после запуска худший сценарий −X%».
4. **Что изменится:** diff параметров слота. Предупреждение: «ваш бот Уровни будет заменён, снимок сохранён».
5. **Автобэктест на ваших монетах:** запускается в фоне, результат появляется в шторке.
6. Кнопка «Запустить».

**«Мои боты»**, карточка своего бота:
- статус: Работает / Ждёт сетап / Пауза: дневной лимит / Демо / Выключен;
- R за сегодня и за 7 дней; открытые позиции; последний сигнал;
- действия: «Пауза новых входов»; «Стоп» с выбором (только новые входы / закрыть всё по рынку / оставить позиции на бирже без сопровождения, с предупреждением). У Veles эти действия разнесены по трём местам [BC §9 п.2];
- «Настройки», «Подобрать», «Бэктест», «Поделиться».

**Экран результата бэктеста:**
- Шапка с автотегами. Теги Veles: мало сделок (< 30), хуже, чем держать монету, Net < 0. Наши дополнительные теги:
  - «Переобучение: вне выборки хуже обучающей части больше чем вдвое»;
  - «p95 просадки > 15R»;
  - «Прибыль сделал один период из четырёх» (walk-forward);
  - «Комиссии съедают больше 30% прибыли»;
  - «MTF-фильтры в бэктесте упрощены» (честная оговорка: в бэктестере SMC использует один датафрейм для всех ТФ, у LEVELS HTF-фильтр выключен [GEN §1.6.3]).
- Кривая: обучающая часть затенена, часть вне выборки яркая; полоса Монте-Карло p5–p95; 4 столбика walk-forward.
- Вкладки «Сделки» и «Настройки».
- Кнопки «Запустить бота», «Подобрать», «Поделиться».

**Экран «Подбор» (Genome):**
- прогресс поколений: популяция точками, точки сходятся к лучшему фитнесу;
- лучший результат на текущий момент;
- таблица «было → станет»;
- две кривые на одном графике;
- кнопки «Применить» и «Отклонить».

Подбор работает только как черновик: diff → бэктест → явное подтверждение. Этот принцип взят из агентских правил OKX [CB §2.10].

**Риск-панель:**
- открытый риск;
- сценарий «все стопы сразу»;
- состояние защит: серия стопов 1/3, дневной убыток −1,2R из −5R, сделок сегодня 2/3;
- переключатели защит и общий стоп по просадке.

**Онбординг-чеклист**, видимый в шапке приложения (вместо «Испытаний» Veles, награда днями Pro, а не деньгами на внутреннем балансе):
1. привязать Telegram для уведомлений;
2. создать первого бота в демо;
3. провести первый бэктест;
4. подключить биржу (ключ без вывода) или Bybit Demo;
5. запустить первый челлендж.

**Тариф:**
- две карточки: «Подписка $69 / 30 дн.» и «За результат»;
- калькулятор;
- в режиме «За результат» месячный леджер: сделки ботов, чистый PnL, high-water mark, начисление.

### 3.5 Ключевые потоки

1. **Гость:** лендинг → песочница → «Запустить такого бота» → регистрация (Telegram, Google или email) → бот уже создан в Демо с выбранными параметрами → чеклист.
2. **Копирование:** витрина → «Копировать» → 7 дней в демо → бейдж → «На биржу» → API-ключ (или Bybit Demo) → автотрейд с подтверждением.
3. **Свой бот:** мастер (стратегия → монеты и ТФ → направление → риск → режим) → бэктест → «Подобрать» → применить → демо или биржа.
4. **Дрейф:** уведомление «live хуже бэктеста на 18 п.п.» → «Подобрать заново» или «Пауза».
5. **Дисциплина:** бот → «Челлендж для бота» → план → дневные лимиты → сезон.
6. **Оплата за результат:** выбор режима → месяц работы → леджер → счёт → оплата. Если не оплачено, после льготного периода ставятся на паузу новые входы.

### 3.6 Правила честности статистики (обязательны для витрины и лендинга)

1. У каждой цифры указан источник: **LIVE** (трекер, с даты публикации), **BACKTEST** (только часть вне выборки), **БИРЖА** (сделки копий).
2. Доходность всегда стоит рядом с макс. просадкой и числом сделок.
3. Перевод R в проценты делаем только с оговоркой «при риске N% на сделку, без реинвеста».
4. Комиссии. В спецификации трекера комиссий нет: R считается по ценам уровней [SIG]. Поэтому на витрине вычитаем ту же модель, что в бэктестере: `fee_r` от 0,12% за круг, с проскальзыванием [GEN §1.6.4]. Подпись: «после комиссий, оценка».
5. На витрину бот попадает только после 30 закрытых live-сигналов или 30 дней работы. До этого у него бейдж «Новый, мало данных».
6. Боты не пропадают молча. Снятые уходят в «Архив» с итоговой статистикой, чтобы не было ошибки выжившего.
7. Считаются все исходы: SL, БУ, EXPIRED по рынку, ручные. Ликвидации копий видны во вкладке «Копии».
8. В счётчик копий попадают только копии, проработавшие не меньше 7 дней. Это защита от накрутки.
9. На каждой цифре есть время обновления.
10. Публичная страница «Как мы считаем» с формулами из [UI §2, §5.2] и [GEN §1.6].

- Репутационный и юридический риск рекламы мартингейла.

### 4.4 Риски, общие для всех вариантов

**Мартингейл и сетка (если дойдёт до B3):**
- Математика. При мартингейле ×2 десятый ордер в 512 раз больше первого, и для такой сетки нужно больше $10 000 (блог Veles: https://veles.finance/ru/blog/post/top-5-bot-setup-mistakes/ [BC §2.5]).
- Справка Veles признаёт: «Multiple bots can enter drawdown simultaneously… may lead to liquidation» [RP #1]. После обвала 10–11.10.2025 часть стратегий в таблицах #SURVIVE1010 помечена «ликвидирован» [BS §6].
- Обязательные ограничители:
  - только спот или плечо не выше 3×;
  - максимум ордеров;
  - потолок суммарного объёма сетки не больше X% баланса;
  - расчёт цены ликвидации до запуска и флаг «в бэктесте была бы ликвидация»;
  - обязательный стресс-тест на 10–11.10.2025, май 2021 и ноябрь 2022;
  - для новичков сначала демо;
  - сетки входят в риск-бюджет счёта.

**Юридические и маркетинговые заявления** (всё ниже нужно проверить с юристом до публичного запуска):
1. **Не обещать доход.** Даже Veles в FAQ пишет «Гарантирует ли Veles доход от торговли? Нет» [SP §2 #12]. На нашем текущем лендинге есть шаг «Получайте прибыль» [CSS index.html, секция `#how`]: убрать.
2. **Реклама финансовых услуг в РФ.** Закон о рекламе (38-ФЗ, ст. 28) запрещает гарантировать доходность. Формулировки нужно проверить.
3. **Цифровая валюта в РФ.** С 2024 года действуют ограничения на рекламу и предложение цифровой валюты неограниченному кругу лиц (поправки в 259-ФЗ). Как подавать сайт RU-аудитории, решать с юристом.
4. **Процент с прибыли, копирование и витрина** в ряде юрисдикций могут считаться управлением активами или инвестиционным советом (в ЕС MiCA: portfolio management / advice). Позиционирование: «мы разработчик ПО», ключи без права вывода, пользователь запускает сам, условия в оферте. Юридическая проверка нужна до включения D14.
5. **Урок Veles про доверие:** предупреждение NSSMC в IOSCO I-SCAN, оценка ScamAdviser «Very Likely Unsafe», фишинговые клоны [RP §1, #5]. Поэтому на сайте нужны юрлицо, контакты, страница «Официальные ссылки» и предупреждение о клонах.
6. **В сравнениях не использовать бренд Veles.** Писать «типичный DCA-бот».

**Данные:**
- После смены режима рынка витрина деградирует: помогают дрейф-детектор и архив.
- Накрутка копий: правило 7 дней.
- Споры по счёту «за результат»: сверка с биржей и выгрузка сделок.

**Нагрузка (одно ядро):**
- Витрина ограничена ~20–30 ботами.
- Пользовательские бэктесты идут в очереди с nice 19, как Genome [PLAN §2.2 п.6].
- Лендинг работает только на предрасчётах.

### 4.5 Рекомендация

**Вариант C.** Сначала ядро A (9–10 недель): слоты, витрина на трекере, бэктест, «Подобрать», копирование, лендинг v1. Витринные аккаунты запускаем за 4–6 недель до публичного старта. Потом A6–A10, потом B1 и B2. B3 — отдельным решением по данным спроса и после юридической проверки.

## 5. Визуальная концепция сайта

### 5.1 Идентичность: оставить красный Liquid Glass

Mini App уже задаёт узнаваемый стиль [CSS app.css]:
- фон от чёрного к бордовому (`#060204` → `#3a0712`) с виньеткой и плёночным зерном;
- стеклянные карточки: `rgba(10,3,6,.46)`, blur 9–16 px, верхний внутренний блик `inset 0 1px 0 rgba(255,255,255,.045)`;
- красное свечение активных элементов (`.glow-red`), фиолетовое для Pro (`.glow-violet`);
- шрифты: Oswald (заголовки капсом), Inter (текст), JetBrains Mono (числа и подписи).

**Исследование не даёт причин менять стиль.** У Veles графитовые нейтрали и пара «оранжевый + фиолетовый» из логотипа, тени почти не используются [VD §1.1, §1.5]. Совет исследования — «своя пара акцентов, глубина через свечение и тени» [VD §7.1]. У нас это уже есть, и стиль заметно отличается от Veles.

**Главная проблема — несогласованность.** Лендинг `index.html` сейчас подключает `tailwind.css` и `aura-theme.css`: чёрный фон, оранжевый `#FF5A1F`, Inter и JetBrains Mono, без Oswald [CSS aura-theme.css, styles.css]. Приложение при этом красно-бордовое. Решение: перевести лендинг на токены `app.css`, а фоновый canvas `aura-bg.js` перекрасить в бордово-красную гамму. Тогда лендинг и приложение выглядят как один продукт.

### 5.2 Токены и правила

| Роль | Токен | Где используется |
|---|---|---|
| Фон | `--bg-0..3` (`#060204`, `#0a0305`, `#1d0509`, `#3a0712`) | Страница, градиент сверху вниз, виньетка, зерно |
| Стекло | `--card` `rgba(10,3,6,.46)` + blur, `--line` `rgba(255,255,255,.085)` | Карточки, шторки, шапка |
| Бренд и действие | `--red` `#ff2a4d`, `--red-glow` | Залитая главная кнопка, активные чипы, свечение «Топ», точка live в шапке |
| Прибыль | `--green` `#3df2a0` | Плюс в R и $, достигнутые TP, растущая кривая |
| Убыток | **новый `--loss`**, например `#ff7a8f` (светлее и холоднее бренда), заливки `--red-dim` | Только текст и контуры со знаком «−» и подписью SL. Залитых красных плашек для убытка нет |
| Live / ожидание | `--amber` `#ffc24b` | Открытая сделка, «ждёт сетап», бейдж LIVE |
| Pro / Genome / «За результат» | `--violet-1/2` `#7c3aed` → `#a855f7` | Тариф, ДНК-визуализация, премиальные бейджи |
| Текст | `--text`, `--muted`, `--dim` | Основной, вторичный, подписи |

**Конфликт «красный = бренд» и «красный = убыток» решаем правилом:** бренд-красный встречается только в заливках действий и свечении. Убыток показываем отдельным текстовым токеном `--loss` со знаком и подписью. На графиках убыточные столбики штрихуются.

Контраст красного на бордовом нужно проверить: мелкий текст красным не набираем.

**Типографика:**
- Oswald капсом: H1 и H2, крупные заголовки карточек;
- JetBrains Mono с табличными цифрами: все числа и микро-подписи капсом 10–11 px с разрядкой. Тот же приём, что капс-лейблы у Veles [VD §1.4] и наш `.label`;
- Inter: основной текст.

**«Жидкое стекло» и движение:**
- Блик: на стеклянной карточке под курсором движется мягкий радиальный блик (CSS-переменные от pointer). Лёгкое преломление краёв через SVG displacement включаем только в hero на десктопе.
- Появление данных: числа «досчитываются» (count-up) только для реальных значений. Новые элементы живой ленты въезжают сверху. Карточка витрины переворачивается и показывает параметры.
- Scroll-story: макет слева «прилипает», шаги меняются справа.
- `prefers-reduced-motion` отключает движение и блики. На мобильных нет WebGL и displacement, фон — статичный градиент.

**Графики** рисуются на клиенте в canvas (решение D3), переиспользуем `frontend/app/chart.js`. У графиков всегда есть оси, период и нулевая линия R. Это прямой ответ на спарклайн Veles без осей [VD §5].

### 5.3 Лендинг по секциям

Каждая секция описана так: что показывает, какой интерактив, откуда данные, чем лучше Veles.

**0. Шапка и лента тренда.**
- Тонкая бегущая строка: тренд BTC по 6 ТФ (▲/▼/↔ и сила) и 24-часовое изменение BTC и ETH. Данные из нашего монитора тренда [UI §4.1 п.2], а не чужого виджета.
- Меню: Витрина · Бэктест · Цены · Челлендж · Помощь. Кнопка «Открыть приложение».
- Чем лучше: у Veles нет живого рыночного контекста на лендинге (не установлен [VD §4]).

**1. Hero: «песочница бота».**
- Слева:
  - H1 «Боты со стопом в каждой сделке»;
  - подзаголовок «Проверь на истории, подбери параметры генетикой, запусти в демо или на своей бирже»;
  - кнопки «Запустить такого бота» и «Смотреть витрину».
- Справа стеклянная панель:
  - чипы стратегий (Уровни · SMC · Объём + MA);
  - чипы монет («активные за 24 ч», как подсказка пар в редакторе Veles [VD §2.4]);
  - направление; ползунок риска 0,25–3%;
  - при смене выбора мгновенно перерисовываются кривая equity и метрики (WR, PF, макс. просадка, N, бейдж «вне выборки»).
- Данные: ночной предрасчёт сетки «3 стратегии × топ-20 монет × 3 пресета» бэктестером Genome в статичный JSON. На запрос посетителя CPU не тратится.
- Кнопка ведёт на регистрацию, выбранная конфигурация сохраняется: после входа бот уже создан в Демо (поток F1).
- Чем лучше: у Veles продукт показан баннером, у нас посетитель «делает» бота за 3 секунды (механика Uniswap и Composer [VD §6 #3, #8]).

**2. «Прямо сейчас»: живая лента и честные счётчики.**
- Лента реальных сигналов витринных ботов: пара, стратегия, направление, статус. Статусы меняются вживую: «TP1 → стоп в БУ».
- Для гостей лента задерживается на N минут (предложение 60), уровни скрыты.
- Счётчики: отслежено сигналов, закрыто с итогом, ΣR платформы за 30 дней, сколько дней работает витрина. Только данные трекера, у каждого время обновления. Никаких «$40M под управлением» без даты.
- Механика Polymarket [VD §6 #5]. Чем лучше: у Veles счётчики без даты и проверяемости [SP §2 #2].

**3. Витрина ботов.**
- Горизонтальная карусель со snap-прокруткой и стрелками, карточки по анатомии §3.4.
- Чипы фильтров: стратегия, риск 1–5, направление, ТФ, «работает в текущем режиме».
- Сортировки: Топ (R / просадка), Новые, Больше копий.
- При наведении карточка переворачивается и показывает «как торгует».
- Внизу ссылка «Архив снятых ботов».
- Чем лучше: бейдж источника, просадка, ось на графике, медиана копировавших, архив [VD §5 «слабое» п.1–2; BS §10].

**4. «Как это работает»: история при прокрутке, 5 шагов.**
- Слева «прилипший» макет экрана приложения, справа шаги:
  1. «Выбери бота» (карточка);
  2. «Проверь на истории» (экран бэктеста с тегами);
  3. «Подбери параметры» (популяция точек сходится);
  4. «Запусти: демо или биржа» (модалка ключа с подписью «ключ без права вывода»);
  5. «Держи дисциплину» (карточка челленджа с дневным лимитом).
- Механика Stripe [VD §6 #2, §7 п.5].

**5. Площадка бэктеста.**
- Крупная версия песочницы: стратегия, монета, период.
- Пресеты стресс-окон: «10–11 октября 2025», «май 2021», «ноябрь 2022».
- Кривая с затенённой обучающей частью, полосой Монте-Карло и автотегами.
- Данные — предрасчёт.
- Чем лучше: Veles сделал стресс-тест разовым конкурсом #SURVIVE1010 [BS §6], у нас он доступен кнопкой всегда.

**6. «Стоп вместо усреднения»: интерактивное сравнение.**
- Две панели рядом: «типичный DCA-бот» (сетка из 10 ордеров, мартингейл ×2) и «бот CHM» (один вход, стоп, риск 1%).
- Ползунок «цена упала на X%»:
  - слева растёт требуемая маржа, приближается ликвидация, с подписью «10-й ордер в 512 раз больше первого»;
  - справа сделка закрыта по стопу: −1R = −1% депозита.
- Бренд Veles не упоминаем.
- Это прямой ответ на боль #1 [RP #1] и на «почему у нас нет сетки».

**7. Genome: эволюция вживую.**
- Анимация популяции: точки поколений, лучший фитнес растёт.
- Человеческое объяснение фитнеса: «WR × PF × объём выборки − просадка, проверка вне выборки, Монте-Карло, walk-forward» [GEN §1.6.8].
- Живые данные: дата последней эволюции и лучший результат по каждой стратегии (`genome_history`).
- Чем лучше: у Veles AI-оптимизация помечена «Soon» [SP §2 #3].

**8. Челлендж: планировщик цели.**
- Посетитель вводит депозит, цель, срок, риск, плечо и получает план в R и $ с предупреждениями: «риск ≥ 3%: пять стопов подряд = −15% депозита».
- Математика `challenge.plan` — чистая функция [UI §6.23], она работает прямо в браузере. Без истории сделок показывается вердикт no_data.
- Кнопка «Начать челлендж».
- Чем лучше: у Veles «Испытания» — это бонусы за действия, а не дисциплина [SP §3.4].

**9. Цены: подписка или за результат, с калькулятором.**
- Три колонки: Free (Уровни, одно направление, 2 сигнала в день [UI §3]), Pro $69 / 30 дней, «За результат».
- Калькулятор (механика Wise [VD §6 #1]):
  - ползунки «депозит» и «чистая прибыль ботов за месяц»;
  - строки «Подписка: $69», «За результат: min(X% × прибыль, потолок)», «В минусовый месяц: $0»;
  - подпись «прибыль считается чистой, после комиссий биржи, с переносом убытка».
- Чем лучше: у Veles процент берётся с валовой прибыли и из предоплаты [SP §3.1].

**10. Безопасность и доверие.**
- Схема: «ваш ключ (торговля без вывода) → наш сервер (AES-GCM) → биржа; деньги всегда на бирже».
- Юрлицо и контакты, страница статуса, «Как мы считаем», «Официальные ссылки и клоны».

- Веб, Telegram Mini App, push-уведомления.
- QR-код для посетителя с десктопа (как у 3Commas [VD §6, таблица]).
- Скриншоты экранов «Мои боты» и карточки сигнала.

**13. Футер.**

### 5.5 Тексты: что убрать с текущего лендинга

Сейчас на `index.html` есть блоки «AI Сканер Сигналов», «Polymarket», «Бэктестинг», «Мульти-Биржа» и шаг «Получайте прибыль» [CSS index.html].
- Polymarket удалён из продукта.
- «AI» вводит в заблуждение: у нас генетический алгоритм и детерминированные движки.
- «Получайте прибыль» — обещание дохода.

Правила текста:
- не писать «пассивный доход» и «гарантия»;
- всегда давать подпись «результаты прошлого не гарантируют будущих»;
- у каждой цифры указывать источник и дату.

### 5.6 Мобильная версия и доступность

- Боковые отступы 16 px, без горизонтальной прокрутки страницы. Горизонтально прокручиваются только карусели со snap.
- Внизу «липкая» кнопка «Открыть приложение».
- На мобильных песочница hero сворачивается в 3 чипа и одну кривую.
- Бюджет LCP < 2,5 с: шрифты подгружаются неблокирующе, как в Mini App [UI §1.1].
- Контраст проверяем по WCAG AA: мелкий текст только `--text` и `--muted`.
- Всё интерактивное доступно с клавиатуры, у графиков есть `aria-label` с ключевыми числами, как у R-шкалы в Mini App [UI §2.1].

### К2. Механики Veles из заметок, которые CONCEPT пропускает

**Влияют на честность и риск (взять в A или явно учесть):**

1. **Простой стоп Veles срабатывает только после исполнения всей сетки.** Пример: перекрытие 15% и стоп 5% дают выход на −20% от цены входа [BC §2.8]. Это и есть скрытый максимальный убыток сделки DCA. Его нужно показать в секции 6 лендинга и заложить в ограничители B3.
2. **Блокировки не только «By position».** Есть лимит числа ботов в сделке и отдельные лимиты Long/Short. Главное: блокировки действуют **только на ботов с фильтрами входа** [BC §5; CB §1]. Это объясняет боль #1 и задаёт минимальный набор для M7.
3. **PnL% у Veles считается без плеча** (при x10 1% в Veles ≈ 10% на бирже) [BC §2.7]. Поэтому «+117% (4x)» на витрине Veles нельзя сравнивать с нашими «% при риске N%» без пересчёта.
4. **Метрики серии убытков:** ожидаемая и фактическая максимальная серия, резерв худшей серии (Worst streak reserve), MAE к депозиту, время в сделках, сравнение с Buy & Hold [BS §1.4]. Для стратегии со стопом главный риск — серия стопов. В карточке бота §3.4 этих метрик нет.
5. **Допущения бэктеста Veles.** Вход по цене открытия следующей свечи. Фитили по умолчанию не учитываются, поэтому стопов в тесте меньше, чем в реальной торговле. Прогрев 300 свечей. Подсказка «SL ≈ 2 × фитиль p0.99». Показывается объём данных: число баров, «история доступна с 2019» [BS §1.1–1.2; VD §2.5]. Наш бэктестер проверяет SL первым на каждом баре [GEN §1.6.4]. Это сильная сторона, её стоит назвать на странице «Как мы считаем».
6. **Indicator Selection показывает только прибыльные варианты.** Это in-sample на 1500 свечах, без проверки PnL [BS §1.7]. Такой отбор победителей повторять нельзя. Внести в §3.7.
7. **Минимальный депозит на карточке и «бот за $1»** [VD §2.3; BS §3], резерв 50% от суммы сделки [RP #1]. У нас риск задаётся в % депозита, а у биржи есть минимальный объём ордера. Значит, у каждого бота есть минимальный рабочий депозит, но в карточке §3.4 такого поля нет.
8. **Дисциплинарные флаги:** «остановить после N сделок», «остановить бота после стопа», реинвест (справка советует его только для стратегий без стопа) [BC §2.4, §2.8]. Это дёшево и ложится на Челлендж.
9. **Режим без фильтров:** бот открывает новую сделку сразу после закрытия предыдущей [BC §2.6]. Нужен ответ в FAQ «почему бот молчит».
10. **Тип маржи ISOLATED/CROSS** на многих биржах один на весь аккаунт [BC §2.4]. Это ограничение для N ботов и для риск-панели.
11. **includePosition:** бот подхватывает уже открытую позицию с биржи [BC §2.4]. Пригодится для «Стоп → оставить позиции» и для возврата позиции под управление.
12. **Снимок настроек хранится внутри результата бэктеста.** Бота можно восстановить из бэктеста или по ID сделки. Edit Bot открывает несохранённую копию [BS §1.4, §1.8]. Это даёт воспроизводимость для `/b/{code}`.
13. **Что происходит по окончании подписки.** У сигналов по подписке при истечении открытые сделки дорабатывают, новые не открываются, бот останавливается с ошибкой [BS §4]. CONCEPT описывает неоплату только для «За результат». Что будет с ботами при окончании Pro, не сказано.
14. **Срок жизни API-ключей.** У Binance ключ по умолчанию действует 3 месяца. Просроченный ключ даёт «Invalid API key», привязку правят вручную; ключ OKX без IP может деактивироваться (low) [SP §7.3; RP #8]. Нужны напоминания.

**Продуктовые и визуальные (решить: брать или нет):**

17. Флаг «Public test»: на бесплатном тарифе тесты публичные и наполняют витрину и рассылку, на платном их можно скрыть [BS §1.1, §10 п.5]. Флаг упомянут, решения нет.

20. Предпросмотр на графике цены в редакторе: сетка, средняя цена, SL, исторические входы. VD называет это лучшим «aha-моментом» Veles [VD §5 п.3]. В варианте A мастер показывает кривую equity, но не входы, SL и TP на графике цены до запуска.

### К4. Внутренние противоречия и проверка выполнимости

- **[критично] D14.** В DEC записано: «процент с прибыльных сделок с месячным потолком (по PnL биржи)». CONCEPT предлагает процент с чистой месячной прибыли по high-water mark и при этом ссылается на D14 как на основание (§0, M9). Это другая модель: D14 ближе к Veles, где берётся процент с каждой прибыльной сделки. Владелец должен явно изменить D14.
- **[критично] Стресс-окна недоступны.** Хранилище свечей держит 365 дней (`cleanup`: `now − 365 d`) [GEN §1.17; M3]. На 08.10.2026 окно 10–11.10.2025 выпадет из истории через 2–3 дня, а май 2021 и ноябрь 2022 недоступны. У BingX-перпов многих монет такой истории нет вовсе. На этих окнах держатся секция 5 лендинга, обязательный стресс-тест B3 и §5.3 п.5 «у нас стресс-тест всегда под кнопкой». Нужен отдельный архив свечей для стресс-окон (BTC, ETH и топ-монеты), иначе эти обещания придётся убрать.
- **[важно] Окно бэктеста Genome — 10–80 дней в зависимости от ТФ** [GEN §1.6.1]. Монте-Карло p95 для шкалы риска считается по тестовым сделкам этого окна, часто их меньше 40. Без порога «мало данных» уровень риска будет шумным. Период бэктеста на карточке и в hero нужно подписывать. Нагрузку от прогонов длиннее окна Genome §5.4 не оценивает.

Факты о Veles переданы в целом точно: цифры, цены, цитаты и ссылки сходятся с заметками. Отклонения — это формулировки сильнее источника (#1, #2, #4, #6 в К1) и одна неверная ссылка (#3). Главные проблемы не в описании Veles, а в наших механиках «честности». Метка «вне выборки» на геномах неверна, потому что Genome отбирает по этим же данным. Бейдж «LIVE» висит на бумажном треке. Витринные боты могут менять параметры. Сравнение с DCA построено против подставного противника. Стресс-окна обещаны на данных, которых нет. Модель оплаты расходится с записанным решением D14. До решения владельца нужно исправить пункты [критично]: К3 #1, #3, #4, #7 и К4 «D14» и «стресс-окна». Остальное можно исправить до публичного запуска.
