# tests/autotrade/m15 — the M15 trade-ops loops against the bot's own code

PLAN_M15 (scratchpad `port/m15/PLAN_M15.md`) ports the bot's background loops (BE monitor, state reconcile,
trade-state cleanup, SL verifier, anomaly detector, orphan sweeper). Every ported behaviour is proved by
vectors the bot produces: a Python driver under `py/` runs the bot's real functions (bot checkout
`/home/user/MAIN_BOT/CHM_BREAKER_V4`, branch `claude/funny-edison-529rg1`, HEAD `1a47ffc`) and writes
`fixtures/*.json.gz`; the JS tests here replay the same inputs through the site code and compare.

## Run

```
cd /home/user/MAIN_BOT/CHM_BREAKER_V4
BOT_TOKEN_CHM=test:token ADMIN_IDS=123 <venv311>/bin/python -I -B \
  /home/user/website/backend/tests/autotrade/m15/py/gen_m15_units.py          # → fixtures/m15_units.json.gz
rm -f /home/user/MAIN_BOT/CHM_BREAKER_V4/signal_registry.json
git -C /home/user/MAIN_BOT status --porcelain                                  # must be empty

cd /home/user/website/backend
npx vitest run tests/autotrade/m15
```

The generators are deterministic: two runs write identical bytes (gzip mtime 0 and no file name in the
header, seeded randomness, no wall-clock or temp-path leaks). Never commit inside the bot checkout; the
harness refuses to finish when the checkout changed (`git status --porcelain --ignored` and the size /
mtime of the ignored files are compared before and after).

## Python harness (`py/m15_harness.py`)

Importing it (before any bot module) gives:

* **Sandbox**: `DB_PATH` / `BOT_LOG_FILE` in a temp dir (the loops' lazy `import bot` opens the log file),
  the test Fernet key, `BOT_TOKEN_CHM` / `ADMIN_IDS=123`, scenario env scrubbed (`RECONCILE_V2_MODE`,
  `PANIC_CLOSE_STREAK`, `POST_CLOSE_COOLDOWN_SEC`, `FUNDING_VELOCITY_*`, `ORPHAN_SWEEP_*`, proxies, Sentry);
  `set_env(...)` sets scenario env (reload the module that reads it at import, e.g. `orphan_sweeper`).
  `user_logger`'s file handler is never created (`USER_ACTIONS` records its lines). `finish()` removes this
  run's `signal_registry.json` and checks the checkout.
* **Clock** `CLK` (wall `1767225600.0` = 2026-01-01 UTC, mono `1000.0`): `time.time`, `time.monotonic`,
  `time.sleep`; `FakeDT` / `swap_dt(fn)` / `patch_module_datetime(mod)` for `datetime.utcnow()` (e.g. the
  `session_hour` of `db_set_trade_result`'s trade_feedback row).
* **`run(coro_fn)`** on `VLoop`, the virtual-time loop of `tests/autotrade/wire/py/drive_wire_diff.py`: the
  clock jumps exactly to the next timer and only when no coroutine, executor thread or aiosqlite job is
  runnable — a DB await takes zero virtual time, so a `wait_for` deadline lands in a trader call, a sleep or
  a scripted latency only. Same-instant timers fire in scheduling order (FIFO) — `_FifoTimerHandle` via
  `VLoop.call_at`, like the JS vclock's `seq` tie-break and the bot on a real clock (CPython's heap alone
  wakes 8 equal sleeps as 1,3,7,6,8,5,2,4, which decides who gets a semaphore slot); the wire driver's
  `VLoop` does the same (its two fixtures were regenerated byte-identical). A cancelled sleep's timer handle
  is cancelled, so it never moves the clock. `task_name()` = the nearest named asyncio task (parents
  followed).
* **`Fakes`** — signature-binding trader fakes: `install(ex, module, [fn, …])` / `install_all({...})`,
  `set(ex, fn, *answers)` (last repeats), `label(value, name)` for test credentials. A call binds
  `inspect.signature(real)` first; a call the real function would refuse raises the REAL `TypeError` text
  (BE1-Q12) and is listed in `bind_errors`. Each call is recorded `{i, t, mono, task, ex, fn, args, kwargs,
  bound, answer}`; `bound` = parameter order with defaults (the binding the site must reproduce). Answers:
  `{"value": v}`, `{"value": v, "err_out": [...]}` (strict reads), `{"raise": {"type", "msg"}}`,
  `{"latency": s, "value": v}`, `{"hang": s|None}` (then `TimeoutError`). An unscripted call is a harness
  error (`errors`). `sigs[ex][fn] = {sig, async}` goes into the fixture.
* **Recorders**: `RecBot(sink)` (`send_message`, `fail_on` substrings raise), `SafeSend(sink)` (bound to
  `telegram_safe.safe_send_message`; `install(*modules)` patches every module-local import; `results`
  `[(substring, result)]`), `CallRecorder` for fire-and-forget collaborators (`metrics.record`,
  `smart_prompts.trigger_after_win`, `trade_autopsy.stream_analyze_closed_trade` → `True` per D23; the
  `self.bot` the bot passes first is recorded as `{"__bot__": true}`), `LOGS` (every logger except noisy
  third-party ones: level, logger, text, task, wall time, exception). `jsonable` never writes a memory
  address: the recording bot is `{"__bot__": true}`, an object with the default repr (or a repr with
  ` at 0x…`) is `{"__obj__": "<qualname>"}`.
* **Cancels vs semaphore hand-overs**: `GuardedSemaphore(n)` (an `asyncio.Semaphore` that records each
  release instant and task) and `guarded_cancel(task, *sems)` — `task.cancel()` that raises `HarnessError`
  when one of the semaphores was released at this same virtual instant by another task (the one case the
  site's `createSemaphore` cannot reproduce, below). Every driver that cancels or shuts down tasks around a
  semaphore (U4's verifier `Semaphore(5)`) uses them; offset such a cancel (e.g. +0.5 s).
* **DB**: `init_db()` (init_db's own kv rows are the baseline the dumps leave out), `seed_users(specs, fakes)`
  (`UserSettings` → `db_upsert_user`, keys encrypted; `raw` columns written verbatim by SQL — NULL, `''`,
  `'0'`, undecryptable tokens), `seed_trades(rows)` (given columns only, in order → same rowids as the site
  seed), `seed_kv`, `sql`, `sql_rows`, `explain`, `dump_db(t_ref, trade_cols, trade_ids, kv_prefix)`,
  `drain_bg()` (awaits `emit_bg`'s `evt_*` tasks and every aiosqlite job of a step).
* **`write_fixture(obj, path)`** — gzip JSON via `tests/exchanges/py/harness.py _jsonable` (Python float
  repr kept; NaN / inf tagged), deterministic bytes.
* **`self_test()` / `self_test_async()`** — exercises all of the above and asserts the contract; its record is
  the `harness` section of `m15_units.json.gz`.

## JS harness (`harness.js`)

* `loadFixture(name)` — `pyJsonParse` + the `_jsonable` tags.
* `setupSiteDb(name)` — a temp site DB with all migrations; call before anything requires `models/database`.
* `seedSite(db, {usersRaw, users, sitePlain, admins, trades, kv})` — the bot's seeded rows in the site tables
  (`users.telegram_username` / `is_admin`, `trader_settings` = the bot's raw `users` columns, `exchange_keys`
  encrypted with `WALLET_ENCRYPTION_KEY` — `'@undecryptable'` gets a ciphertext that fails — `signal_trades`
  in the same order, `engine_kv`). `insertSiteUser`, `insertSiteKey` for site-only cases.
* `dumpSiteDb(db, opts)` — `dump_db`'s shape on the site tables.
* `makeFakeTraders({calls, sigs, clock, labels, byTask})` — `traderFor(ex, demo)` whose handles answer the
  bot's recorded calls in order per `(ex, fn)` (or `(task, ex, fn)` where the bot runs concurrently — the
  verifier's `Semaphore(5)`). Each site call is bound to the bot signature (`bindToSig`: positional args in
  the bot's parameter order, a trailing options object = the keyword-only parameters, camelCase →
  snake_case) and compared with the bot's `bound`; answers are served the same way on the virtual clock
  (latency / hang cancellable by `waitFor` and `runInScope`). `problems()` lists argument mismatches, extra
  and missing calls. The inverse map — any bot call `(args, kwargs)` → the site's positional call — is
  `toSiteArgs` in `tests/exchanges/callMaps.js` (PLAN_M15 §5 is the authoritative table).
* `makeDeliveryRecorder({clock, failOn, safeResults})` — `sendMessage(bot, uid, text, opts)` (the runtime's
  safe send), `bot.sendMessage` (raw sends, admin alerts with `adminIds`), `alertAdmins`, `sendText`; records
  in the Python shape `{via, t, task, uid, text, parse_mode, kw, …}`.
* `makeLogCapture(clock)` — `debug … critical`, `exception(msg, err)`; `at(minLevel)` → `[[level, text]]`.
* `createVClock` (`tests/autotrade/core/vclock.js`) — `run(promise)`, and `runUntil(limitMono)` for loop
  shells that never settle (abort the scope afterwards). Same-instant timers fire by `seq` (FIFO), as the
  Python `VLoop` does.
* `vclockSleep(clk)` — `asyncio.sleep` on the virtual clock that honours the cancel scope AND removes its
  timer when cancelled (asyncio's cancelled sleep handle). Drivers pass it as the site runtime's sleep
  (`ctx.sleep`, the trader runtime's sleep, every in-pass sleep under `waitFor` / `runInScope`) — never
  `asyncio.cancellableSleep(clk.sleep)`: that one leaves the abandoned timer behind, `clk.run` (which drains
  every timer) jumps to its deadline, and every call, log, delivery and DB `ts` of the next step comes out
  late. `makeFakeTraders` uses it for latency / hang answers.
* `sameSet`, `firstDiff` — order-insensitive comparison for `emit_bg` / `create_task` side effects of a pass
  (BE2-O10); the first differing path.

## Site deviations recorded here (U1)

* **Keys come from `exchange_keys`** (the bot's nine `users` columns): the row of (user, exchange) with label
  `'default'` first, then the newest; each field decrypted on its own (an undecryptable field → `''` with
  the bot's `_decrypt_key` ERROR line verbatim, as `db/core.py` returns `""` per column).
* **D5**: an exchange outside `AUTOTRADE_EXCHANGES` reads as no keys in every reader (PLAN_M15 §1.6 / C-11);
  the vectors run with all four exchanges enabled (the bot has no such switch).
* **`username`** = `users.telegram_username`; NULL reads as `''` (the bot's column default) — a bot row with
  an explicit NULL username (only possible by SQL) reads `None` in `db_get_user`, `''` on the site.
* **NOT NULL columns**: `trader_settings` cannot hold the bot's NULL (e.g. `auto_trade`); the seed keeps the
  column default, which `_from_db` gives a NULL anyway (falsy / the dataclass default).
* **Microtask vs loop iteration**: a woken semaphore waiter resumes on a microtask in JS, one loop
  iteration after `release()` in the bot. Hand-overs WITHOUT a cancel happen at the same instants and in
  the same FIFO order. A cancel or abort that another task delivers at the same virtual instant as a slot
  release, after it (a timer due then that fires after the releasing one, the shutdown cancel), cannot be
  reproduced: the bot's woken waiter raises `CancelledError` at acquire and the slot passes on, the site's
  waiter has already entered its body and its first call leaves (its `checkCancelled()` still passes) — the
  per-task traces and the recorded calls differ (`same_instant_cancel`, pinned in `asyncio.test.js`). Only
  a cancel issued by the releasing task's own step is reproduced (`woken_then_cancelled`). Rule: no vector
  puts a cancel or abort on a release instant — `guarded_cancel` refuses one.

## Site deviations recorded here (U2)

* **D24 range**: a valid Python int outside ±(2^53 − 1) in `ORPHAN_SWEEP_*` is refused like a malformed one (JS
  numbers / timers cannot hold it; the bot would sleep "forever" or fail hourly). Sleeps past 2^31 − 1 ms are chunked.
* **C-5 at the shell level**: after a pass (or a DB read) returns, the shell checks the cancel scope inside its try —
  an abort that came while the pass awaited a non-cancellable call is the bot's CancelledError at that await (the
  stopped line); what the pass did after that await on the site still ran (U3-U10 add their own checkpoints).
